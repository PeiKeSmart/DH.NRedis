# 跨项目接续协议（用户级 · 全项目适用）

## 了解用户（偏好速览）
- 中文交流；指令简洁，偏好“直接推进 + 关键处确认”；重大口径先确认再落文。
- 三条主线：**不遗漏**（跨电脑 / 跨会话可接续）、**口径一致**（全项目统一）、**有记录**（决策含原话、可追溯）。
- 排查优先本地源码（不反编译）；密钥不做可配置项、凭据不明文落盘；不使用他人签名文件。
- Windows 脚本与编码约定（BOM / PS 5.1 外部命令 / 国内镜像）见「国内镜像与 Windows 脚本约定」一节。

## 项目接续流程
- **开工先读（存在则读，按序）**：`.github/copilot-instructions.md` → `docs/项目接续指南.md` → `docs/用户档案.md` → `docs/项目记忆.md` → 决策/审计文档最新节。
- **机器自愈（有则快跑）**：项目内若存在 `tools/continuity/install-global-instruction.ps1`，接续时先静默运行它（幂等：本机用户级指令缺失即补装、过旧即更新、一致则不动，输出一行结果）；该项目 `.vscode/tasks.json` 已配“打开项目自动自检”，双保险。改本协议内容后：把 `版本：` 行递增，然后跑 `Pek.RPanlServer\tools\continuity\_sync-user-instruction.ps1`（全盘扫描，把本机副本字节级铺到所有仓库模板）与 `_commit-user-instruction.ps1`（逐仓库只提交模板文件）。**别只改一处** —— 副本分散在不同仓库，落下一处就是下次漂移的种子（2026-11-05 全盘扫到 **110 个副本**、版本从 2026.10.10.4 参差，根因就是旧脚本把 16 个仓库路径硬编码）。
- **用户级指令自身的改动纪律（2026-11-08 教训，务必遵守）**：**本机副本可能是旧的** —— 那天本机停在 `2026.11.05.3`，而 9 个仓库副本已是 `2026.11.06.2`（多出「回归脚本与测试门槛」一节），直接改本机副本再全盘铺开，就把较新的内容盖掉了。规矩：**改之前先跑 `Pek.RPanlServer\tools\continuity\_sync-user-instruction.ps1 -Check`**（只读巡检；退出码 **3 = 有副本比你新** → 先把最新副本回灌本机、合并后再改；**1 = 有副本落后或同版本不同内容** → 可同步；**0 = 全盘一致**）；**内容一变就必须递增版本号**；同步脚本已内置版本守卫（仓库副本版本更高则**拒覆盖**，只有显式 `-AllowDowngrade` 才强行降级），并且以退出码区分三种状态。
- **每轮收尾（务必）**：① 决策/审计文档新增一节（**含用户原话**）；② 同步记忆——把本机工作记忆复制进项目 `docs/项目记忆.md`（记忆位置：`%APPDATA%\Code\User\workspaceStorage\<本项目对应目录>\GitHub.copilot-chat\memory-tool\memories\repo\*.md`；若项目内有 `tools/continuity/sync-memory.ps1` 则直接运行，需在项目根目录运行或传 `-ProjectPath`）；③ 跑回归验证并如实汇报。
- **新电脑首次回灌（防覆盖）**：新机器首次运行 `sync-memory.ps1` 前，先把仓库镜像 `docs/项目记忆.md` 内容并入本机记忆再回灌——防止稀疏的本机记忆覆盖完整镜像；镜像随 git 版本化，误覆盖可从提交历史找回。
- **装备任意项目（用户说“装备接续基建”时）**：AI 自建——`.github/copilot-instructions.md`、`docs/项目接续指南.md`、`docs/用户档案.md`、`tools/continuity/`（含 `sync-memory.ps1`、`install-global-instruction.ps1` 与模板，可从任一已装备仓库整体复制）、`.vscode/tasks.json`（打开项目自检），并同步 `docs/项目记忆.md`；**无需用户复制任何文件**。
- **换电脑**：项目数据走该项目的 git 远程；本用户级指令随 Settings Sync（勾选 "Prompts and Instructions"）自动漫游；每台新电脑首次打开任一已装备项目时，其自检任务会自动补装本指令。

## 打包、发版与覆盖升级（用户偏好 · 全项目适用）
- **打包即升版本**：发布打包脚本默认在打包时自动递升补丁版本号（每产出一次包版本唯一）；次版本升号用显式参数；版本守卫拦截「同版本内容变化」；需重打同版本时显式关闭（-NoBump 或 -Force，视脚本而定）。
- **工具链用最新**：系统 PATH 与构建脚本一律使用最新稳定工具链（如 zig 0.17.0）；旧版本仅留档，不作为默认。
- **打包部署一律走 zig 交叉编译**：对外部署包（Linux）必须用 `cargo zigbuild` 交叉编译产出（x64 = `x86_64-unknown-linux-musl`，arm64 = `aarch64-unknown-linux-musl`）；本机 Windows 的 `cargo build --release` 只作开发验证包，不作为交付物。打包脚本必须内置 zig 分支，zig 查找顺序 `CARGO_ZIGBUILD_ZIG_PATH` → `E:\Soft\zig-*`（取最新）→ 项目 `tools\zig`；缺 zig/cargo-zigbuild 时明确报错，不得静默退回本机编译。
- **升级一律走「覆盖替换」、免手动停启**：星尘（Pek.RAgent）默认**影子模式**（进程运行 `shadow/` 下的影子副本，源文件不被占用），Windows / Linux 均可直接覆盖源程序文件；代理按 5 秒周期检测变动 → 重建影子副本 → 自动重启（数秒级）。部署脚本与文档必须支持并说明该方式，不得要求「先停止 → 再替换 → 再启动」。
- **部署设计约束**：安装脚本以绝对路径注册子服务（`-AddService`，默认影子）；程序保持「配置就绪才运行」守卫（占位配置保持停用），避免无效配置被反复拉起。

## 编译提速规范（用户偏好 · 全项目适用）
- **分档选最快的构建方式**：写代码用 `cargo check`（增量秒级、**不做链接**、不产二进制）；本地调测 / 起服务验证用 `cargo build --profile fast`（或 `cargo run --profile fast`）；`--release` / zig 交叉只用于发布，不用于日常验证。
- **Windows 宿主一律用 `rust-lld` 链接**：`%USERPROFILE%\.cargo\config.toml` 加
  `[target.x86_64-pc-windows-msvc]` + `linker = "rust-lld.exe"`（随 rustup 工具链自带，无需另装）。
  实测本机增量 debug `cargo build` **13.76s → 2.66s**；瓶颈是 MSVC `link.exe`（PDB 写入 + Defender 实时扫描），不是 CPU。
  只作用于 MSVC host，`cargo zigbuild` 交叉编译不受影响（已回归验证 exit 0）。
- **每个 Rust 项目必须自带 `[profile.fast]`**：`inherits = "release"` + `lto = false` + `codegen-units = 16` + `incremental = true`。
  缺了它 `cargo build --profile fast` 直接 `exit 101`（PekSendToMo 踩过）。实测改一个文件：**fast ≈4s / 配 rust-lld 后增量仅 1.3~1.75s vs fat LTO ≈3m10s**；`--release`（fat LTO）只给发版，不要为了“快”而长期用 dev 跑压测。
- **先分清「下载慢」还是「编译慢」**：`cargo build -v` 看是 `Downloading` 还是 `Compiling`；只有 `Compiling` 占大头才去调 profile / 换链接器 / 换编译目标，否则白忙。
- **保存即检查 / 自动重启**：Rust 项目装 `cargo-watch`，用 `cargo watch -x check`（或 `-x run`）代替手动重复构建。
- **前端改动不重编后端**：Vue/Vite 项目开发期用 `vite dev`（热更新 + /api 代理）；构建产物目录（如 `wwwroot`）是独立资源、刷新页面即生效；只有后端源码变化才需要 cargo。
- **sccache 按需**：仅在经常 `cargo clean`、频繁切 target/profile 或 CI 共享缓存时启用（`[build] rustc-wrapper = "sccache"`）；它不缓存本 crate 重编与 LTO 链接，不能解决「改一个文件两分钟」。
- **杀软排除**：代码目录与 `CARGO_TARGET_DIR` 建议加入 Defender 实时扫描排除（本机已排除 `F:\Soft\...`），否则每个 obj/pdb 落盘都要过一遍扫描。
- **口径纠正**：**`ziglang` 与编译速度无关** —— `cargo zigbuild` 是**交叉编译工具链**（产出 Linux musl 包），不是提速手段；WSL2 也不是通用银弹，见下一节。
- **★ 验证一律走分档，不要动不动打包（用户已 3 次强调：2026-10-27「先不要打包，不要动不动就打包，这样很浪费时间，都没有完全确认我的信息」；2026-10-28「不要动不动又打包」；2026-11-05「先不要动不动就打包，我记得我提过很多次了，你要验证不是应该按快速运行验证的方式么？」）**：
  - **自测 = 快速运行**：`cargo check`（看错误）→ `cargo build`（dev 档出 exe）→ **起本地实例实测**（换端口 + 临时数据目录 / `--data-dir`；前端用 `vite dev` 或构建脚本按需）→ 浏览器/接口验证。
  - `--profile fast` 只用于**交付前**验证；`--release` / `cargo zigbuild` 交叉**只用于发版**。
  - **打包脚本只在用户明确说「打包 / 出包 / 我要部署」时才跑** —— 打包会递升版本号、`dist/` 越堆越多，且耗时远大于验证；汇报里也不要写「顺手打了个包」。

## WSL2 规范（用户偏好 · 全项目适用）

- **WSL2 不是「编译更快」的银弹**：收益来自 **ext4 本机盘 + Linux 原生工具链 + 与部署环境一致**。源码放 `/mnt/<盘>`（Windows 盘）跨文件系统访问**比 Windows 原生更慢**；要对比就把仓库镜像到 `~/work` 再构建。
- **离线安装（不依赖 Microsoft Store，2026-11-05 实测）**：`dism /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart` + 同名 `VirtualMachinePlatform`（返回 **3010 = 成功、需重启**）→ 装 WSL msi → `wsl --import <名> <目录> <rootfs.tar.gz> --version 2`。重启前 `wsl --update` 会**挂住**、`wsl --import` 报 `HCS_E_SERVICE_NOT_AVAILABLE`，均属正常。
- **`/etc/wsl.conf` 必须 `appendWindowsPath=false`**：否则可能调到 Windows 版 `cargo` / `rustc`，报莫名错误；需要时用绝对路径。
- **参考实现**：`PekSendToMo/scripts/setup-wsl.ps1`（幂等 7 步：自检功能 → 装 WSL → 校验 rootfs → 导入 → 建用户 → apt 换源装依赖 → 装 rustup），其它项目可直接复制改参数。

## 国内镜像与 Windows 脚本约定（用户偏好 · 全项目适用）

- **crates 镜像**：每个 Rust 项目根目录放 `.cargo/config.toml`，配 `[source.crates-io] replace-with = "rsproxy-sparse"`（`sparse+https://rsproxy.cn/index/`）—— 缺这个文件的仓库首次编译会从 crates.io 慢速拉包（同一台机器上实测卡十几分钟）；`replace-with` 是透明替换，Cargo.lock 里的源地址不变、不产生锁拖动。
- **rustup 镜像**：`RUSTUP_DIST_SERVER=https://rsproxy.cn`、`RUSTUP_UPDATE_ROOT=https://rsproxy.cn/rustup`。
- **系统镜像必须实测再选（2026-11-05，同一文件）**：`mirror.nju.edu.cn` **36 MB/s** > `mirrors.ustc.edu.cn` 12 MB/s > 官方 `cloud-images.ubuntu.com` **0.58 MB/s**；TUNA / BFSU / SJTU 的 `ubuntu-cloud-images` 路径 **404**（不镜像该子目录）。GitHub releases ≈ 1.5 MB/s。不要默认「清华一定行」。
- **`curl` 报 `CRYPT_E_NO_REVOCATION_CHECK (0x80092012)`**：Windows schannel 查不到吊销列表，加 `--ssl-no-revoke`；**不要**改用 `-k` 关掉证书校验。
- **含中文的 `.ps1` 用 UTF-8 with BOM**（PS 5.1 按 ANSI 读无 BOM 文件，中文会乱码）；跑 python 前设 `$env:PYTHONIOENCODING='utf-8'`。
- **PS 5.1 调外部命令**：`$ErrorActionPreference = 'Stop'` 会把外部程序写 stderr 当成**终止错误**，`wsl.exe` / `cargo` / `git` 的正常报错会直接把脚本炸掉且不给提示。必须封装：临时 `Continue` → 执行 → 取 `$LASTEXITCODE` 与输出 → 还原。
- **`WSL_UTF8=1`** 让 `wsl.exe` 输出 UTF-8，但 PS 5.1 仍按 ANSI 解码 → 中文全乱码；同时要把 `[Console]::OutputEncoding` 设成 UTF-8（用完还原）。

## 复用优先 · 禁止重复造轮子（用户偏好 · 全项目适用）

- **任何功能、任何大小的改动，写码前的第一动作都是检索**——不是只有“重启/升级/影子”这类才查：加一个接口、加一个字段、做一个弹窗、写一段部署脚本、改一行前端，都先检索。顺序固定：**公共库 → 兄弟项目 → 本仓库既有实现**，三处都查过才允许新写；查不到也要在交付说明里写一句「查过 X / Y / Z，无可复用实现」。
- **按功能域查，别只按功能名查**（同一能力常叫别的名字）。先认领域，再按该域的常见同义词检索：

  | 功能域 | 必查关键词（命中任一就去看实现） | 通常的落点 |
  |---|---|---|
  | 数据库 / ORM / 建表 / 迁移 | `Dal`、`EntityModel`、`sync_schema`、`Database.toml`、`db_admin`、`Query`、`Where`、`readwrite`、`shards` | `Pek.RCode` |
  | 鉴权 / 会话 / 令牌 | `panel_auth`、`AuthLevel`、`PanelSession`、`jwt`、`claims`、`revoke` | `dhrust::net::panel_auth`、`Pek.RPermissions` |

- **全盘检索命令（每轮至少跑一条，把输出当证据留着）**：
  ```powershell
  Get-ChildItem 'G:\Code\Rust','G:\Project' -Recurse -Filter '*.rs' -ErrorAction SilentlyContinue |
      Select-String -Pattern '<关键词1>|<关键词2>|<关键词3>'
  ```
- **命中之后看什么**：① 签名是否可直接用；② 是否只差参数/选项/feature；③ 需要改动就**改公共库并连带回归其它消费方**，不要“复制一份再改”；确需特化只留薄壳胶水（参考 Pek.RAgent 的 `service.rs` / `sys.rs`）。
- **`dhrust` 能力对照（别再手写这些；完整清单见库 README）**：
  - 日志/配置/时间/签名/加密：`logs`、`config::{toml,xml}`、`web`、`sign::{password,challenge,salted_sha256_hex}`、`secret`、`version`、`times`、`io::{read_tail,base_dir,safe_replace_file,write_all_text_atomic}`；
  - 网络：`net::{http,http_client,router,controller,static_files,listener,panel_auth,panel,login_guard,port_available,tcp_check,api_rpc}`；
  - **星尘**：`staragent`（注册/注销/`handle_cli`）+ **`staragent::{services,local_port,locate_config,find_by_program,operate,restart_program}`**——本地控制客户端（查子服务/启停重启，走 `net::api_rpc` UDP 规范通道，与 C# 星尘字节级互通；**面板“重启服务”一律用它，不要自己拼 HTTP `/RestartService`**）；
  - **升级/部署**：`upgrade::{extract_archive,extract_program,backup_file,replace_file,shadow_deploy_base,actual_program,handoff,spawn_helper}`（`actual_program`：影子副本 → 源程序路径，升级/重启都必须落到源程序）、`zip`、`patch`、`service`、`fileman`、`term`、`plugin`、`sys::*`、`threading`、`cache::TtlCache`。
- **同一逻辑出现第二份就下沉**：两个项目各写一份同款实现 → 下沉到公共库（`dhrust` / `Pek.RCode` 等），**两个消费方一起切换**并跑回归；下沉时把坑与边界写进文档/注释（如「tokio 运行时内不得 block_on」「toml_edit 删键会带走注释」这类教训）。
- **不要用“复制一份再改”解决差异**：差异用参数/选项/feature 表达。
- **交付前自检（硬性）**：本轮新增/修改的每个函数、结构、脚本函数，都要能回答「公共库里为什么没有可复用的」，并给出**检索证据**（命令 + 命中/未命中）；面板类功能逐项过一遍：日志、鉴权、限流、静态资源、配置回写、升级重启、文件管理、ZIP、审计、WAF、用户与权限——这些在生态里都已存在。
- **反例（2026-10-27，必须记住）**：给 hlktech-iot-mqtt 面板做「重启服务」时没先检索，自写了一整套 HTTP `/GetServices` + `/RestartService` 客户端，还为此多引入一个 feature；实际上 `dhrust::net::api_rpc`（UDP，与 C# 星尘互通）、`Pek.RPanlServer/src/restart.rs`、DHDeploy `star_agent::operate` 早有同款能力。用户当场质问：**「目前做的这些都是没有参考我们自己的Rust项目么？要不然为什么每个项目感觉都是单独实现的」**，随后补充：**「写码前的第一动作就是检索不是只有重启这一块吧」**——即检索必须覆盖**所有功能域**，不是只为某一个功能补作业。当天已把能力下沉为 `dhrust::staragent` 客户端 + `dhrust::upgrade::actual_program`，Pek.RPanlServer 与 HlktechIoT 一起切换。

## 源码依赖自动拉新（用户偏好 · 全项目适用）
- **触发条件（满足任一条即先拉新）**：
  ① **要动它** —— 本机以**源码/路径引用**的依赖库（如 DH.RustBase、Pek.RCode、Pek.RAdmin 等）编译报「缺少被引用的 API/函数」或疑似落后；
  ② **要评它** —— **凡要对已装备 / 依赖仓库做分析、判断、对比之前，先 `git fetch` 看清远端**。只看本地工作树 = 拿「落后的本地」当基准，结论必错（2026-10-12 因此误判 DH.RustBase「缺件」并越界写入，事后 `reset --hard` + 快进才平掉）。
- **做法**：在**原仓库内增量拉新（fetch + 快进）后**再继续（复测 / 分析）；不重克隆（避免大件重下与丢失本地状态）。
- **分支也要看全**：对比 / 判断「有没有」之前先 `git branch -r`；实现可能只在非默认分支（例：HlktechIoT 的 Broker RPC 配置只在 `origin/2.0`，当前 `dev` 没有）。用 `git show origin/<分支>:<路径>` 或 `git grep <符号> origin/<分支>` 核对，不能只搜当前检出分支。
- 拉新纪律：先查工作区状态（有本地改动先说明/stash）；只做快进（--ff-only）；GitHub 直连受限时按既有约定用 IP 直连（http.curloptResolve）；拉新得到的提交号写入当轮收尾台账。
- **边界**：拉新是「读」，**不等于可以写** —— 要改别的仓库时**另问**；各自项目各自仓库处理。
## 实测优先 · 禁止猜测（用户偏好 · 全项目适用）

- **任何「性能 / 容量 / 行为 / 谁在用」的结论，必须有实测数据或源码证据（附 `文件:行号`），不许靠推算或印象**。用户 2026-10-29 原话：**「不能猜」**（同一轮里猜错三次后要求写入全局指令）。
- **反例（都真实发生）**：
  - 断言「放弃在线表会让写放大变大」→ 实测相反（每跳写 21 列 → 只写设备表 2 列，降一个数量级）。
  - 用**陈旧二进制**跑测试得到 `FAILED` → 源码其实是对的；`Copy-Item` 恢复文件会保留旧 `LastWriteTime`，cargo 不重编。改完源码跑测试前必须先更新 mtime，否则「结论」是假的。
  - 断言「多个 heartbeat 实例都会写在线表」→ 实际共享订阅下一条消息只投给组内一个实例。
- **正确做法**：
  - 行数 / 耗时 / 参数上限 → 写 `#[ignore]` bench 或用例**实测**，把数字与命令写进决策记录（例：「SQLite 变量上限 32766：3 列 6000 行=30000 参数 OK、8000 行=40000 参数报 `too many SQL variables`」）。
  - 「这张表/这个字段谁在用」→ 全仓 grep 列出 `文件:行号` 再下结论；说「没人用」必须附 grep 命令与结果。
  - 修复必须验证用例**有效**：**撤掉修复 → 用例必须失败**；只看到「跑了通过」不算验证。
  - 结论被后续证据推翻时，**立刻纠正，并在决策记录里写明「前一判断错在哪」**，不要悄悄改口。

## 回归脚本与测试门槛（用户偏好 · 全项目适用）

- **每个已装备项目必须有一键回归入口**：`tools/regression.ps1`（Windows 宿主）或 `tools/regression.sh`，一条命令串起「构建 → 单元测试 → 冒烟/端到端 → 关键对拍」，**退出码 0/1** 可直接接 CI。不允许"每次靠人工回忆该跑哪几条命令"。
- **改动即回归**：任何源码 / 脚本 / 配置改动完成后先跑一键回归再交付；汇报必须贴**实际输出**（构建 0 错误、测试失败 0、冒烟退出码），不接受口头"已通过"。
- **阈值写进脚本、只能抬高**：测试总数不得下降（脚本内置下限，例如"通过数 ≥ 现有基线"），冒烟必须 0 失败；新增用例后同步抬高阈值，**降低阈值必须在决策记录写明依据**。
- **区分「真失败」与「已知缺口」**：已知缺陷允许以 `KNOWN` 输出但**不计入 PASS**，并在决策记录/issue 留痕；工件缺失必须显式打 `SKIP` + 原因，**禁止静默 `return`**（会让"全绿"变成假象）。
- **回归脚本自身要可靠（Windows / PS 5.1 实战坑）**：
  - 含中文的 `.ps1` 必须存 **UTF-8 with BOM**（无 BOM 会被按 ANSI 解析、直接语法报错）；
  - 调外部命令后判 `$LASTEXITCODE`（`$ErrorActionPreference='Stop'` 会把正常 stderr 当终止错误，脚本被炸掉还没提示）；
  - 调 python 前设 `PYTHONIOENCODING=utf-8`，否则子进程中文输出乱码；
  - 报告落 `artifacts/regression/report-<时间戳>.txt`，便于回溯与对比。
- **一次性验证不算护栏**：本次会话临时跑过的命令必须沉淀进回归脚本，否则下次改同一处又没保护。
- **禁止为了变绿改断言**：测试失败先判"代码错"还是"基线过时"；确属基线的，给出实测数据后在决策记录里说明再调整；破坏性回归优先修代码而不是改期望值。

## 数据库连接命名与在线管理规范（用户偏好 · 全项目适用）

- **连接名唯一来源 = `Model.xml`，禁止自创**（不许 `main` / `proxy` / `db` / `default` 这类名字）。
  用户 2026-11-08 原话：**「不可能还不按规则随便建数据库链接吧」**。
- **`Model.xml` 可能有多连接（多库），语义分两级**（用户 2026-11-09 原话：
  **「每个项目的 `Model.xml` 会有多个 ConnName 才是正常的吧」**、**「只有表上没有 ConnName 的会用文件中默认的那个，
  如果表上有的那就会连接表指定的这个」**）：
  - 模型级 `<Option><ConnName>` = **默认连接**；
  - 表级 `<Table ConnName="Xxx">` = 该表**覆盖**到指定连接（多库/分库）；
  - 所以「从 Model.xml 分析有多少个连接」= **模型级 + 全部表级 `ConnName` 去重**，逐一补齐。
    实测生态 109 个 `Model.xml` 里 **36 个是多连接**（`DH.Core` = DG + Log + Membership + Regions）。
  - 各项目模型级连接名举例：`Pek.RPanlServer`=Platform、`Pek.RAgent`=Traffic、`Pek.RDbProxy`=Admin、
    `HLZX.EIP`=Main、`HlktechIoT`=DH/IOT、`Pek.Proxy`=DH。
  - **建表也必须按连接过滤**：表级 `ConnName` 优先、没有则归模型级。不区分就会把别的库的表建到本库，
    而表级连接指向的库反而一张表都没有（`Pek.RCode` 2026-11-09 已修：`Dal::sync_schema_for(conn, include_model_level, include_network)`；
    `Databases::store` 传连接名；未注册的表级连接由 `open_auto_sqlite` 建库后自动 `sync_schema_for` 建表）。
- **C# 侧另有两个框架级连接**：`Membership`（成员/权限）、`Log`（系统日志）。权威参考
  `src/Pek.DeepSeekProxy/appsettings.json` 的 `ConnectionStrings` = `DH` / `Membership` / `Log`（默认全是本地 SQLite）。
  所以合规的连接集合 = **Model.xml 的 ConnName + Membership + Log**，缺一个都算不合规。
- **必须自动补齐，不许让运维手工建连接**。约定文件生成或加载时：
  1. 读 `Model.xml` 的 `ConnName` 作为默认连接与业务库连接名；
  2. 缺 `Membership` / `Log` 就补（**只补缺、绝不覆盖**用户已配的）；
  3. 旧的/自创的连接名自动改名，**连接串原样保留**（数据文件不变 → 历史数据与账号不丢），
     `[External] UserConnection` 之类引用一并跟上；
  4. 回写前留 `.bak` + 原子写，并打日志写清「改了什么、为什么」，保证**可追溯且幂等**（二次启动不得再改）。
- **在线管理必须成套**：面板对每条连接可 **增 / 删 / 改 / 测试连通 / 切换 / 绑定用途**；
  「连接名」输入框默认预填模型 ConnName —— 切库是**改它的连接串**，不是另起一个名字。
- **切换语义**：默认连接恒为 `Model.xml` 的 `ConnName`（C# 实体按 ConnName 选库）。
  填别的名字只当作**新增一条连接**（如配主站库），不改业务库归属、不触发数据迁移。
- **连接串落盘转义**：内存态字符串用**单反斜杠**（`Data\DH.db` 在 Rust 里写 `"Data\\DH.db"` 之前先想清楚），
  由渲染层负责 TOML 转义。写成两倍反斜杠会在 **Linux 上创建文件名带反斜杠的库**（Windows 看不出来，最难发现的一类坑）。
- **验证门槛**：动连接相关逻辑后必须实测「旧配置升级不丢数据 + 二次启动幂等 + 面板能看到全部连接」；
  参考实现 `Pek.Proxy`：`tests/legacy_template.rs`（8 项）与手工升级演练（旧 `main` 配置 → 自动变 `DH` 并补齐三连接）。

## Pek.RCode 模型驱动规范（用户偏好 · 全项目适用）

- **模型是唯一真相源**：`Entity/Model.xml` ← `Tools/sync-model.ps1` ← C# 权威模型（`G:\Code\YRY.Framework\src\HlktechIoT.Data\Model.xml` + 实体类 `[BindIndex(...)]`）。**要加索引 / 改结构 → 改权威模型两端后跑 `sync-model.ps1`**，不要在运行时打补丁。用户 2026-10-29 原话：**「如果什么都是随便用的话，那我们弄的 Pek.RCode 通用类岂不是就没有什么作用了？」**
- **禁止（发现即改，并连带回归其它消费方）**：
  - **运行时改模型**：`model.tables.retain/push/remove`、`model.indexes.push/retain` 去「绕过」结构问题（曾在运行时裁掉一条唯一索引，造成模型与实际结构不一致）。
  - **手写 DDL**：`create table` / `alter table` / `create index` 代替 `Dal::sync_schema()`。`sync_schema` 是**增量安全**的（缺表建表、缺列补列、缺索引补索引，**不删列、不改列类型**），不要因为「怕改列」就手写。
  - **绕过 Pek.RCode 的裸 DML**：`session.execute("insert/update/delete ...")` 会跳过拦截器（`UpdateTime` 等时间列不刷新 → 2026-10-28 心跳批量写事故即此类）。
  - **重复定义表名 / 列名常量**：物理名以模型 `TableName` 为准。
- **允许的例外（必须写注释说明原因）**：模型 API 表达不了的聚合查询（`group by ... having`、`sum(case when ...)`）；不在模型内的外部表（如 NewLife `Area` 地区库）；只读探活 `SELECT 1`；元数据查询（`pragma` / `sqlite_master` / `index_list`）；测试代码。
- **`ERROR 1062 Duplicate entry for key 'xxx'` 的处理顺序**：先判断「这条唯一索引**该不该存在**」（谁加的、谁需要）→ 不该存在就**从模型两端删掉**；该存在才去清脏数据。**不要**先 `try/catch` 吞掉或先手写 `drop index` 掩盖。

## 后台配置页规范（用户偏好 · 全项目适用）

- **新增 / 修改配置项必须走完整保存链路**：视图字段（`name="..."`）→ 控制器 Action 参数 → 赋值到对应 `Setting.Current` → `Save()`；只加页面字段不补保存逻辑＝假功能。用户 2026-11-03 原话：「系统配置页加了保存的实际逻辑没加吗？」

- **参考实现先查全部分支**：见「源码依赖自动拉新」——实现可能只在 `origin/2.0` 等非默认分支，不能只搜当前工作区。

## HTTP 服务 WAF 规范（用户偏好 · 全项目适用）
- **凡是长驻 HTTP 服务（面板 / API / Agent 本地接口），一律接 `pek_rwaf::Waf` 中间件**，不许各项目自己写 UA 黑名单或防火墙逻辑（2026-10-26 用户原话：「这套WAF的规范是不是也可以帮我接入到全局用户指令中通用」；RAgent 是既有范式，新项目照抄）。
- **默认从严**：用 `WafConfig::admin_api()` 预设——SQLi / XSS / 路径穿越 / 命令注入 = `Block`，`csrf_guard = true`，`block_malicious_bots = true`；面板前缀写进 `sensitive_prefixes`（该前缀下禁一切机器人，`Monitor` 自动升级为 `Block`）。
- **豁免要「精准 + 内存态」**，禁用「整站关掉检测」这种一刀切：
  - 机器对机器接口（`/Api`、`/api`、`/pek`、`/star`）→ `set_forced_skip_bot_prefixes`（调用方 UA 常是 curl / python-requests / HttpClient / RestSharp，会被误判成扫描器）；**攻击特征检测仍然生效**；
  - 「内容天然含引号或 SQL 关键字」的查询 / 导出接口（日志原文、审计 keyword、文件内容预览）→ `set_forced_skip_attack_prefixes`，否则必然误伤；
  - 必须用 `set_forced_*`（内存态）而不是只写配置：面板保存会把配置写全字段，容易把豁免清空。
- **CC 限流（`rate_limit_per_min`）默认关闭**：分钟级阈值极易误伤「缓存命中的高频正常调用 / 内部轮询」。准入交给 IP 白名单 + 业务限流（如 `[RateLimit]`）；确要开必须**先算业务峰值**并写进决策记录。
- **`loopback_bypass`**：生产可留 `true`（本机工具/脚本免检）；**写 WAF 测试时必须置 `false`**，否则从 127.0.0.1 发起的用例会全部「放行」，测了等于没测。
- **两侧都要有测试**：①拦得住（恶意 UA / SQLi / XSS / 路径穿越 / 跨站 POST → 403）；②不误伤（机器 UA、空 UA 探活、面板日志与审计关键词、同源 POST → 非 403）。只测一侧等于没做。
- **可观测**：`Config/Waf.toml`（camelCase 字段，mtime 热重载）必须在 `-status` 与面板「关键配置」里可见（启用状态 / 模式 / CSRF / CC），别让运维猜「到底开没开」。
- **早拒＝不读 body 就拒（最省带宽，默认要做）**：HTTP 层必须装「头阶段」检查，在**收 body 之前**判两件事：① 声明的 `Content-Length` 超上限 → 直接 413（无上传接口的服务上限取 **256 KB 级**，别沿用 64 MB 默认值）；② 恶意 UA / 黑名单 IP / 扫描路径 / 查询串注入特征命中 → 直接 403。钩子用 `dhrust::net::http::HttpServerOptions.early_guard` + `pek_rwaf::Waf::check_head` + `WafRequest::from_head`；body 级规则仍交给路由内 WAF 中间件（只有过了早拒的请求才读 body）。**早拒计入「拦截次数」，但不得再计一次请求总数**，否则统计翻倍、拦截率算错。测试要能用「只发请求头、一个字节 body 都不发」拿到 403/413 并断言耗时可忽略——那才证明没等 body。
- **攻击必须可视化**：面板要有「安全（WAF）」卡——拦截数 / 请求总数 / 拦截率、近 1 分钟与 5 分钟、按原因分类、Top 来源 IP，以及当前策略（模式 / CSRF / CC / 豁免前缀）；统计用纯内存原子计数、零轮询零 IO。用户要的是「一眼看出有没有被攻击」，不是让运维翻日志。
- **真实 IP 必须穿透反代（否则 WAF 等于没开）**：WAF 默认只看 TCP 对端——反代（nginx 等）之后对端恒为 `127.0.0.1`，一旦 `loopback_bypass` 生效就是**整体放行**，同时 IP 黑名单、Top IP、CC 全部失真。服务端必须提供「**仅当对端是回环**时才采纳 `X-Forwarded-For` 首段」的开关（`pek_rwaf::Waf::set_trust_forwarded_for(true)`，与业务层 `client_ip` 同一口径），并随配置变化同步；测试必须覆盖「带 XFF 的黑名单 IP 被拦 + 正常 IP 放行」两侧。（2026-10-26 审计发现：这是接入 WAF 时最容易漏、且后果最严重的一项。）
- **早拒也要认可信签名**：若启用了共享密钥签名放行，头阶段检查必须**先验签**再判 UA/机器人——否则已签名的机器请求会被 UA 规则提前拒掉；CSRF 同样可提前判（纯头，无需 body）。
- **连接层必须有上限与超时（否则 WAF 挡不住打点）**：`max_connections`（超限直接丢连接，不分配线程）+ `header_timeout`（防 Slowloris：连上后慢慢发请求头）+ `request_timeout`（读 body 与处理整体超时，超时返 408）。**`thread_per_connection` 模型下不设上限＝线程可被打爆**；纯文本服务建议 512 连接 / 10s 头超时 / 30s 请求超时起步。
- **body 检测别被 Content-Type 绕过**：body 扫描要按 `body_scan_limit`（默认 64 KB，可配）进行；**只有 JSON/表单的服务必须开 `body_scan_all_types`**，否则攻击者改个 `Content-Type: application/octet-stream` 就跳过 body 特征检测。
- **HTTPS 两种形态都要支持（部署形态不确定）**：① 服务端自己终止 TLS（独立部署，证书留空则自签，配了路径缺失就**启动失败**而不是静默降级成 HTTP）；② 前置 nginx 终止 TLS（`Tls=false` + `TrustForwardedFor=true`，XFF 用**覆盖**而非追加）。文档必须给出两种的完整配置样例，别只写一种。
- **拦截日志要按「IP + 原因」去重**（1 秒窗口、容量有界）：攻击洪峰时每次拦截写一行会把日志 IO 放大成瓶颈；但**统计计数不能受去重影响**（要有专门用例守住这条）。

## 登录口令规范（用户偏好 · 全项目适用）

- **唯一标准（C# / Rust / PHP 混用环境一律照此，不要再各系统各一套）**：**存储**一律 `dhrust::sign::password`（与 C# `NewLife.Security.SaltPasswordProvider` 字节级互通），**算法固定 `md5+sha1`**——`sha1` / `sha512` 档**只认明文**，一选就丢掉「前端 MD5 传输」能力（`sha512` 是 C# 默认值，共库项目要显式切到 `md5+sha1`）；**传输**统一「**前端先 `md5(明文)`（32 位小写）再提交**」，后端必须**同时接受明文与 MD5**（C# `Verify` 对 `md5`/`md5+sha1` 档本就是双分支、`dhrust` 已对齐、PHP 只需加一个 `md5` 分支）；**设置/改密接口一律收明文**（服务端 `Hash` 入库），只有登录接口收 MD5。
- **MD5 传输是「纵深防御」，不是「链路安全」**（2026-10-26 用户定调：一套通用方式）：它防的是**明文出现在反代日志 / API 调试工具 / 抓包工具**里；**HTTPS 仍然必须**（见下条）。带盐存储（`md5+sha1`）防「库泄露被反查」；`pass-the-hash` 与「令牌明文过网」由 **HTTPS + 令牌短时效**兜底——**绝不能拿 MD5 当 TLS 的替代**（无 HTTPS 时 MD5 摘要被抓到仍可重放）。
- **按链路形态分两档（同一档内必须完全一致，不许各写一套）**：
  - **A 档 · 有域名 + HTTPS**（面板 / 站点 / 管理后台）：存储 `$md5+sha1$…`，**前端 MD5 传输**；TLS 兜住链路，MD5 只防「明文落到反代日志 / 调试工具」。
  - **B 档 · IP + 端口直连（无域名、常无 TLS）**（如 Pek.RAgent、DHDeploy.Agent）：存储 `sha256(盐:密码)`，**挑战式登录**——`digest = SHA256(salt + ":" + 密码)`、`response = SHA256(nonce + ":" + digest)`；实现统一走 **`dhrust::sign::challenge::ChallengeStore`**（nonce 一次性 + TTL + 防用户名枚举），**不要各项目自己写 nonce 表**；同时兼容「明文口令」输入以支持脚本/旧前端。
  - **判定口径**：**能否保证全程 TLS** → 能则 A 档，不能则 B 档（B 档的防重放能力就是替 TLS 兜底）。
- **迁移期双接受 + 自动升级**：后端先兼容「明文 / 已 MD5 / 旧式无盐 MD5 / 旧算法值」，登录成功即自动重写为 `$md5+sha1$…`（`verify_and_upgrade`）；非 C# 口径的旧值（如自写的 `salted_sha256`）无法升级时**明确提示重设一次密码**，并写进决策记录。
- **链路安全只有一条正解：HTTPS**。有域名 → 反代或程序内置 TLS + 公共证书；**无域名（Agent / 管理端直连 `IP:端口`）→ 自签叶子证书**：`CA:FALSE` + SAN 写**全部本机 IPv4**（现代浏览器只看 SAN，IP 必须是 `IP:` 类型）+ 有效期 10 年 + 面板一键生成/下载 + 运维**导入一次信任**即可绿锁直开。
- **绝不「每台机器各建一个 CA，再让运维全部信任」**：CA 私钥落在被管理的机器上，等于给那台机器签发「可冒充任意站点证书」的能力，风险远大于省下的几次导入。
- **无 TLS 时的现实防线**（**不防嗅探、只防爆破**，必须在部署文档里写明）：只绑内网/回环 + IP 白名单 + 强口令 + `login_guard` 限流 + 失败锁定 + 令牌短时效 + 禁止公网暴露。


## 资源与带宽惯例（用户偏好 · 全项目适用）
- **适用范围：所有项目、所有进程**——服务端 / Agent / 采集器 / 定时任务 / 工具 / 客户端 / 面板与前端，不只是集群里的某两个进程；**新增或修改任何周期行为（Timer、轮询、watch、心跳、缓存刷新、巡检）都按本节自检**。
- **核心口径**：任何程序都要尽量少占 CPU、内存、磁盘 IO 与网络带宽，**非必要不做周期性全量劳作**。（2026-10-24 用户原话：「要尽量减少 RAgent 本身的压力和性能及资源还有网络带宽，RPanelServer 同样也要考虑这些。非必要不要经常性的去占用消耗」；随后明确：这条适用于**所有涉及到的项目**，不止这两个。）
- **周期任务必须变化驱动 + 缓存**：心跳 / 采集 / 巡检按「签名」比对（配置文件的 mtime + 长度、白名单 / 名单字符串、上次快照值），无变化时只做元数据或内存比对，**不读盘、不解析、不重算**。
- **周期报文只带变化项**：未变化字段发 `null`（对端保留旧值），不要每跳重复上传几 KB 清单；实测站点摘要从每 60 秒 ~8 KB 降到 ~0.6 KB。
- **源头过滤无意义数据**：无域名 / 仅回环的占位站点、临时挂载盘、系统伪目录等，一律在产生处剔除，不让它进入上报、统计与界面。
- **新增周期任务前先算账**：给出「单次耗时 + 每分钟 / 每小时累计开销」并写入决策记录；超过单核 1% 或 1 MB/分钟带宽的方案必须先论证。
- **面板轮询一律带 `document.hidden` 守卫**，后台标签页不空转；常驻轮询只允许必要项（如资源卡 3 秒）。
- **日志 / 审计只记有意义事件**：不要为每次轮询 / 每跳心跳写一行审计；高频路径用聚合计数或降采样。
- **ORM 脏更新的适用边界（Pek.RCode）**：`DirtyState` 只记录「被 setter 改过的列」，**不读库**；缓存来自 `find` 命中 `SingleCache` / `EntityCache`，是另一套机制。适合业务实体局部修改（改 1 列就写 1 列）；**高频外部数据写入（心跳 / 上报）或含大文本列且写频繁的表不要用实体脏更新**——用表级 API + 进程内快照 diff（否则会多一次读，且整表缓存会把大字段全缓存）。
## 日志与错误信息规范（用户偏好 · 全项目适用）
- **凡失败 / 异常 / 跳过 / 重试，必须输出可定位的具体原因与上下文**；禁止只给没有信息量的笼统文案（"操作失败""服务不存在或查询失败""请求失败"这类）。
- **每条失败日志至少包含三要素**：① **做什么**（对象 + 动作，如"升级替换 dhdeploy-agent-rust"）；② **为什么失败**（具体原因）；③ **关键上下文**（路径 / 端口 / HTTP 状态码 / 响应体片段 / 命令行输出关键行 / 参数）。
- **分类文案不可混用**：传输层失败（`Connection refused` / `timeout`）、HTTP 层失败（状态码 + 响应片段）、业务判定失败（响应里没有目标项，附片段）必须用不同文案，便于一眼分辨是哪一层出的问题。
- **禁止吞异常**：有业务含义的路径上不得出现 `catch {}` / `let _ = ...` 丢弃错误；至少 `warn` 一条含错误摘要。返回给前端的消息可以简短，但**日志必须完整**。
- **截断而非省略**：响应体 / 命令行输出等长内容按合理长度截断（如 200~500 字符）后记录，不要整段丢弃也不要全量倾倒。
- **面向运维**：看到日志就能确定下一步（哪一侧、哪个环节、该查什么），不需要上机复现或反复猜测。
- 合入前自检：本次新增的每个 `Err(...)` / `map_err` / `catch` 分支，文案是否满足上述三要素。
